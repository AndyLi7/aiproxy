# MEASURED-HANDOFF-1 — no-task measured relay accounting

Base: `a192140dd0276eaeabe6a28e16699957dcd7429f`. Local-only implementation in `codex/b2-measured-handoff`. No production, staging, push, supplier generation or existing database changes.

## Connected behavior

- The real public relay and retry entries create an opaque per-attempt intent from their existing server price. `AdmitRelayExecution` creates the outer producer alongside the original use and inner execution, before conversion/upstream HTTP. The handle follows the actual `HandleResult`; no request/use-ID string reconstructs it.
- Inner `DoHelper.RecordReturn` still certifies only its own body/response cleanup. The outer writer commits its frozen usage, paired log and final/evidence-only handoff in one transaction. It records outer return only after result persistence, summary and tracing finish normally. Failed persistence or panic leaves active; a successful handoff followed by failed return write does not disappear.
- Nonfinal retry evidence has no chargeable log and never becomes a final outbox. Each retry has its own source; a previous attempt cannot publish a later channel's final result. Same-capability duplicate handoff verifies identical immutable facts and reuses the committed outbox.
- A no-task measured outbox with a durable source is claimed together with an execution offer. Actual worker Accept precedes renewal/business. Existing three-minute `ProcessingToken` and timestamp precision are retained; same-token valid extension uses the current persisted deadline. Accounting/HTTP action guards, parked/failed/completed receipts and token clearing share the original owner transaction.
- Lock order is control → original relay execution → use → source → usage → claim journal → log. No supplier/wallet operation runs under a DB lock. Context propagates through journal waits and existing no-context accounting APIs using the accepted original parent.
- Token-clearing writes capture a private authenticated release receipt with the pre-write deadline; final fresh DB-clock checks roll back all writes on expiry. Normal body return → renewal stop/join → durable exit. Panic/Goexit/failed exit writes retain active. Old expired active records survive a lawful new claim; an old worker cannot use the new owner's authority.
- The final paired log’s stable identity (request/operation/group/token/channel/model/currency/version/upstream) is also frozen and rechecked under its last row lock. Frozen amount and original wallet operation remain unchanged. Remote consume accepted/local receipt rejected stays unknown. Existing replay-safe wallet recovery replays the same operation; non-replay-safe attempted evidence is not cleared. A completed log remains evidence for the wallet callback, not proof the wallet or executor is finished.

## Optional schema and explicit limits

`core/migrations/channel-measured-handoff-v1/{sqlite,postgres}.sql` are isolated drafts only. Protocol `9/v1` was unused on this base (producer occupies `8/v1`); two additive tables store measured producers and claim invocations. No existing table or business TTL changes, no automatic migration. SQLite/PostgreSQL draft replay is tested. MySQL is absent-extension compatibility only; an installed extension is rejected.

Absent/never-activated/late-installed storage never creates historical coverage. A source-less historical usage stays compatible and unproven. Before compatibility persistence, both owned APIs with no execution capability and the legacy final/evidence wrappers reject an already-covered original resource (group/token/operation bound through its durable use). This lookup only denies fallback; it never grants a capability. Actual production Handle success/error wrappers preserve the opaque handle; no naturally reachable handle-loss path was found. Partial/wrong-version/missing-column installations reject. A database-loaded copy of a covered usage cannot replace the private accepted claim, including renewal. First accounting executor requires verified membership; later exact executor facts may reuse the stored historical proof. Source failure does not authorize new unverified executors.

Shared admin/nested DoHelper callers without the outer intent retain the old unproven behavior. If a conditional image-billing candidate resolves to another billing mode, this batch does not certify that other path: its outer source remains conservatively active. A result lost before the handoff transaction commits cannot be reconstructed here; it remains unknown and never authorizes inference replay. Final failed or immutable measurement-pending outboxes are not newly made claimable. Outer `returned` means result-writing stack returned, not successful inference or money settlement.

All uses remain open. No closure, continuous historical coverage, all-replica fence, global watermark, general async worker coverage or safe-disable completion is claimed.
